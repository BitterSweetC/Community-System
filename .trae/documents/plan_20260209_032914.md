I will implement pessimistic locking across the Finance, Recruitment, Club, and Activity modules to ensure data consistency and prevent race conditions.

### 1. Repository Layer Updates
Add `findByIdForUpdate` methods with `@Lock(LockModeType.PESSIMISTIC_WRITE)` to the following repositories to enable row-level locking:
*   **`ClubRepository`**: For safe balance updates and member management.
*   **`RecruitBatchRepository`**: For managing recruitment quotas and concurrent applications.
*   **`ClubFinanceRepository`**: For atomic transaction status updates.
*   *(Note: Activity repositories were addressed in the previous step but will be verified).*

### 2. Service Layer Implementation

#### **FinanceService (`FinanceServiceImpl`)**
*   **`approveTransaction`**: 
    1.  Lock the `ClubFinance` transaction record.
    2.  Lock the `Club` entity using `findByIdForUpdate`.
    3.  Perform balance calculation and update.
    *   *Prevents*: Concurrent approvals causing lost balance updates (e.g., two admins approving different expenses simultaneously).

#### **RecruitService (`RecruitServiceImpl`)**
*   **`reviewApplicationFinal`**:
    1.  Lock the `RecruitBatch` entity.
    2.  Check if `approvedCount` exceeds `quota` (if quota is set).
    3.  Proceed with status update and member addition.
    *   *Prevents*: Exceeding recruitment quotas due to concurrent approvals.
*   **`submitApplication`**:
    1.  Lock the `RecruitBatch` entity.
    2.  Perform `isPresent` check and membership check.
    3.  Save application.
    *   *Prevents*: Duplicate applications from the same user (double-click issue).

#### **ClubService (`ClubServiceImpl`)**
*   **`addMember`**:
    1.  Lock the `Club` entity.
    2.  Check if user is already a member.
    3.  Save new member.
    *   *Prevents*: Duplicate member records.
*   **`applyDissolution`**:
    1.  Lock the `Club` entity.
    2.  Re-check `hasPendingTransactions` and active activities.
    3.  Update status to `DISSOLVING`.
    *   *Prevents*: State inconsistency where a club is dissolved while a new activity/transaction is being created.
