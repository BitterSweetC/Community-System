# 通知系统全面升级计划

为实现您提出的四个通知需求，并确保系统架构的一致性和高性能，我制定了以下实施计划。

## 1. 核心定义更新 (Core)
**目标**：扩展消息模型以支持社团广播，并定义通用的消息队列常量。
- **修改 `RabbitConstants.java`**：
  - 新增 `COMMON_NOTIFICATION_QUEUE` (通用点对点通知队列)
  - 新增 `CLUB_BROADCAST_QUEUE` (社团广播通知队列)
  - 定义相应的 Routing Key。
- **修改 `NotificationMessageDTO.java`**：
  - 新增 `clubId` 字段，用于广播通知。

## 2. 基础设施配置 (Infrastructure)
**目标**：确保所有模块都能正确发送和接收 JSON 格式的消息，修复序列化问题。
- **community-notice (消费者)**：
  - 更新 `RabbitConfig.java`：声明新的队列（Queue）并将它们绑定到交换机（Exchange）。
- **community-activity / recruit / club (生产者)**：
  - 在这三个模块中分别创建 `RabbitConfig.java`，配置 `Jackson2JsonMessageConverter`。
  - *注意：这是为了确保发送的消息是 JSON 格式，避免之前的反序列化错误。*

## 3. 消息监听逻辑 (Consumer)
**目标**：处理接收到的消息并触发通知业务。
- **修改 `NotificationListener.java`**：
  - **监听通用队列**：收到消息后，调用 `notificationService.sendNotification` 发送给特定用户（复用现有逻辑）。
  - **监听广播队列**：收到消息后，调用 `notificationService.notifyClubMembers` 给社团全员发送通知。

## 4. 业务逻辑实现 (Producer)
**目标**：在关键业务节点触发消息发送。

### 4.1 招新审核通知 (Recruit Module)
- **修改 `RecruitServiceImpl.java`**：
  - 在 `reviewApplicationFirst` (初审) 和 `reviewApplicationFinal` (终审) 中。
  - 根据审核结果（通过/拒绝），组装消息并通过 `RabbitTemplate` 发送到通用队列。

### 4.2 社团审批通知 (Club Module)
- **修改 `ClubServiceImpl.java`**：
  - 在 `approveClub` 方法中。
  - 社团状态激活后，发送消息通知申请人（社长）。

### 4.3 活动取消通知 (Activity Module)
- **修改 `ActivityServiceImpl.java`**：
  - 在 `deleteActivity` 方法中。
  - **删除前**：查询所有已报名（Signup）的用户。
  - **遍历发送**：为每个用户发送一条“活动取消”的通知消息。
  - 最后执行删除操作。

### 4.4 社团公告通知 (Notice Module)
- **修改 `NoticeController.java`**：
  - 在 `createNotice` 方法中。
  - 如果是社团公告（`clubId != null`），发送一条消息到 **广播队列**（携带 `clubId`）。
  - 由 Listener 异步处理全员通知，提高接口响应速度。
