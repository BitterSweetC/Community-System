# 社团解散与删除功能改造计划

本计划旨在实现社团管理员申请解散（带冷静期）和系统管理员强制删除（立即执行）的双轨制社团生命周期管理功能，并增加财务、活动等前置检查及定时清理机制。

## 1. 领域模型与基础设施调整
### 实体类增强
- **`Club` 实体**:
  - 新增 `dissolutionReason` (解散原因)
  - 新增 `dissolutionDate` (进入解散流程的时间)
  - 扩展 `status` 状态枚举: 增加 `DISSOLVING` (解散冷静期), `DISSOLVED` (已解散/软删除)
- **辅助服务接口**:
  - `NotificationService`: 模拟发送验证码和通知（邮件/短信）。
  - `FinanceService`: 模拟财务检查接口（检查是否有未完成流水）。
  - `ActivityRepository`: 增加查询是否有进行中活动的方法。

## 2. 核心业务逻辑实现 (`ClubService`)
### 社团管理员功能
1.  **发送解散验证码 (`sendDissolutionCode`)**: 校验权限，生成验证码并通过 `NotificationService` 发送。
2.  **申请解散 (`applyDissolution`)**:
    - **前置检查**: 验证码正确性、无未完成财务流水、无进行中活动、成员清退情况（可选或仅提示）。
    - **状态流转**: `ACTIVE` -> `DISSOLVING`。
    - **数据记录**: 记录解散原因和时间。
    - **通知**: 通知所有成员社团进入解散冷静期。
3.  **撤回解散 (`withdrawDissolution`)**:
    - **权限**: 仅社团管理员在冷静期内可操作。
    - **状态流转**: `DISSOLVING` -> `ACTIVE`。
    - **清理**: 清空解散原因和时间。

### 系统管理员功能
1.  **强制解散/删除 (`forceDissolve`)**:
    - **权限**: 仅系统管理员。
    - **逻辑**: 跳过冷静期，忽略部分非关键检查（如强制停止活动）。
    - **状态流转**: `ACTIVE`/`DISSOLVING` -> `DISSOLVED`。
    - **通知**: 通知社团管理员及成员。
    - **审计**: 记录操作日志。
2.  **恢复社团 (`recoverClub`)**:
    - **权限**: 仅系统管理员。
    - **状态流转**: `DISSOLVED` -> `ACTIVE`。

## 3. 定时任务与自动化 (`ClubCleanupTask`)
- **启用定时任务**: 在主程序启用 `@EnableScheduling`。
- **自动流转**:
  - **冷静期结束**: 每日扫描处于 `DISSOLVING` 状态且超过 7 天的社团 -> 自动转为 `DISSOLVED`。
  - **最终清理**: 每日扫描处于 `DISSOLVED` 状态且超过 30 天的社团 -> 执行物理删除或归档（本次实现打印日志模拟归档）。

## 4. 接口层 (`ClubController`)
新增以下 API 端点:
- `POST /api/clubs/{id}/dissolve/code`: 获取验证码
- `POST /api/clubs/{id}/dissolve`: 申请解散 (参数: 验证码, 原因)
- `POST /api/clubs/{id}/dissolve/withdraw`: 撤回解散
- `DELETE /api/clubs/{id}/force`: 强制解散 (系统管理员)
- `POST /api/clubs/{id}/recover`: 恢复社团 (系统管理员)

## 5. 验证计划
- 编写单元测试或集成测试模拟社团解散流程。
- 验证状态流转是否符合预期（冷静期、强制删除）。
- 验证前置检查（如有活动进行中是否阻止解散）。
