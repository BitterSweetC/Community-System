# 校园社团管理与招新系统 - 需求规格说明书

## 1. 引言

### 1.1 目的
本文档用于系统化阐述“校园社团管理与招新系统”的业务范围、功能需求、非功能需求、用户角色及外部接口，为后续的架构设计、开发实现、测试验收提供标准依据。

### 1.2 背景与目标
高校社团数量多、类型丰富，传统管理方式分散（Excel/微信群/纸质报名），存在信息不透明、数据重复、流程低效等问题。系统旨在：
1. 支持社团信息统一展示与检索，提高曝光度与招新效率。
2. 规范社团招新流程（报名、审核、录取、通知）。
3. 提供活动发布、报名、签到、总结的全生命周期管理。
4. 提供成员分层与权限控制，强化社团内部治理与数据安全。
5. 为校级管理部门提供监管与统计视图，辅助决策。

### 1.3 项目范围
系统覆盖社团从“招新—成员管理—活动运营—公告通知—资源（场地/物资）申请—绩效考核”主要环节。首期版本聚焦：招新、社团管理、活动管理、公告通知、统计报表、基础权限。

### 1.4 用户角色定义
- **游客（Visitor）**：未登录用户，仅可浏览公开的社团列表、社团详情、公开活动信息。
- **学生（Student）**：已登录的普通学生用户，可报名社团、查看个人申请状态、报名活动、接收通知。加入社团后自动获得该社团的成员身份。
- **社团管理员（ClubAdmin）**：社团内部管理人员（涵盖原社长、部长、副部长等角色），负责社团日常运营管理。通过细粒度权限点控制其具体能力范围（如：是否可审批招新、是否可发布公告、是否可管理成员角色、是否可申请资源等）。
- **系统管理员（Admin）**：校团委或系统管理人员，拥有全局监管权限，负责社团审核、社团冻结/解冻、全局统计报表、系统参数配置、操作审计等。

**角色与权限说明**：
- 成员身份通过"加入状态"标识（试用成员、正式成员、已离会），而非独立角色。
- 社团管理员通过权限点实现差异化管理能力，例如：
  - 社长：拥有所有社团管理权限
  - 部长：拥有活动管理、成员管理权限，但无社团信息编辑权限
  - 干事：仅拥有活动签到、公告查看权限
- 采用"基础角色 + 权限点"模型，既简化角色数量，又保持灵活性。

### 1.5 术语定义
- 招新批次：某社团在指定时间范围内开展的一轮招新活动。
- 报名表单：用户提交的加入社团的申请数据集合。
- 活动：社团组织的线下或线上事件（如讲座、比赛、培训）。
- 资源申请：对学校公共资源（教室、场地、设备）的占用申请流程。
- 权限模型：通过角色 + 资源访问策略控制行为范围。

## 2. 总体描述

### 2.1 业务目标概述
系统提供“一站式”社团数字化运营平台，实现信息集中展示、流程可追踪、数据统计可视化、权限分层管理、安全合规。

### 2.2 业务流程概览
1. 社团注册/导入 → 系统管理员审核 → 社团上线。
2. 发布招新批次 → 学生在线报名 → 社团管理员初审 → 社团管理员复审 → 录取通知 → 自动生成成员档案。
3. 活动创建 → 审批（可选）→ 公告发布 → 报名 → 签到 → 结果统计与总结存档。
4. 成员生命周期：报名 → 审核 → 试用成员 → 正式成员 → 离会/转岗。
5. 公告通知：社团内部通知 / 全校广播式公告。
6. 数据统计：报名转化率、活动参与度、社团活跃指数、成员流失率等。

### 2.3 功能分类
- 招新管理
- 社团档案与信息展示
- 成员与角色权限管理
- 活动管理与报名签到
- 公告与消息通知（站内信 / 邮件 / 微信订阅消息 可选）
- AI智能助理与个性化推荐
- 统计分析报表
- 系统管理与安全审计

### 2.4 运行约束
- 技术：后端 Spring Boot 3.x，前端 Web（Vue3/React）。
- 部署：Docker 容器，Linux 云主机；可扩展至 K8s。
- 浏览器兼容：Chrome/Edge 最新两个大版本。
- 数据合规：遵循高校数据管理规范与用户隐私保护政策。

### 2.5 假设
- 学校提供统一认证（OAuth2 / CAS）可对接；若无则自建帐号体系。
- 邮件/短信/微信能力通过第三方服务接入。

## 3. 功能需求 (FR)

### 3.1 账号与认证 (FR-AU)
- FR-AU-01 用户可使用学号+初始密码登录并强制首次修改密码。
- FR-AU-02 支持系统管理员创建社团管理员账号。
- FR-AU-03 支持 JWT 或 OAuth2 令牌鉴权与刷新。
- FR-AU-04 支持忘记密码邮件重置（可选）。

### 3.2 社团信息管理 (FR-CLUB)
- FR-CLUB-01 系统管理员可审核待注册社团并通过/驳回。
- FR-CLUB-02 具有社团信息编辑权限的社团管理员可编辑社团简介、Logo、分类、标签、展示图片。
- FR-CLUB-03 游客与学生可按名称、分类、热度搜索社团。
- FR-CLUB-04 展示社团活跃度指标（成员数、活动数、近期动态）。

### 3.3 招新与申请管理 (FR-RECRUIT)
- FR-RECRUIT-01 具有招新管理权限的社团管理员可发起招新批次（设置时间、名额、说明、表单字段）。
- FR-RECRUIT-02 支持自定义报名表字段（文本、单选、多选、附件上传）。
- FR-RECRUIT-03 学生可在线提交报名，查看状态（已提交/初审通过/复审通过/已拒绝）。
- FR-RECRUIT-04 具有初审权限的管理员可批量初审、添加评语；具有复审权限的管理员最终确定录取结果。
- FR-RECRUIT-05 支持导出报名数据（CSV/Excel）。
- FR-RECRUIT-06 录取后自动生成成员档案并分配默认成员状态。

### 3.4 成员与角色权限 (FR-MEMBER)
- FR-MEMBER-01 支持成员档案：基础信息（姓名、学号、联系方式）、加入时间、成员状态（试用/正式/已离会）、参与活动次数、积分。
- FR-MEMBER-02 支持四种基础角色：Visitor（游客）、Student（学生）、ClubAdmin（社团管理员）、Admin（系统管理员）。
- FR-MEMBER-03 社团管理员可为成员分配社团内权限点，包括但不限于：
  - 招新审核权限（初审/复审）
  - 活动管理权限（创建/编辑/删除活动）
  - 公告发布权限
  - 成员管理权限（查看/编辑成员信息、调整成员状态）
  - 资源申请权限
  - 社团信息编辑权限
- FR-MEMBER-04 支持社团内自定义岗位名称（如：社长、副社长、部长、干事等），岗位与权限点绑定。
- FR-MEMBER-05 社团管理员可调整成员状态（试用 → 正式 → 离会），状态变更记录可追溯。
- FR-MEMBER-06 支持成员积分或徽章体系（可选，可用于激励机制）。

### 3.5 活动管理 (FR-ACT)
- FR-ACT-01 具有活动管理权限的社团管理员可创建活动：主题、类型、地点、人数上限、报名起止时间、需签到标识。
- FR-ACT-02 学生/成员可报名，若超额进入候补状态。
- FR-ACT-03 支持活动二维码签到与手工补签。
- FR-ACT-04 支持活动出勤统计与自动生成总结模板。
- FR-ACT-05 活动结束后生成归档记录，支持评论与评分（可选）。
- FR-ACT-03 支持活动二维码签到与手工补签。
- FR-ACT-04 支持活动出勤统计与自动生成总结模板。
- FR-ACT-05 活动结束后生成归档记录，支持评论与评分（可选）。

### 3.6 公告与通知 (FR-NOTICE)
- FR-NOTICE-01 具有公告发布权限的社团管理员可发布社团公告。
- FR-NOTICE-02 系统管理员可发布全校或分类公告。
- FR-NOTICE-03 成员可查看未读公告并标记已读。
- FR-NOTICE-04 支持消息推送策略（站内+邮件/微信订阅消息）。

### 3.8 AI智能助理与个性化推荐 (FR-AI)
**AI智能体定位**：构建主动感知、智能决策、自然交互的"校园智能助理"，解决信息过载问题，提升用户体验。

**3.8.1 智能问答与咨询 (FR-AI-QA)**
- FR-AI-QA-01 支持学生通过自然语言提问，系统智能解答社团相关问题（如：社团介绍、招新时间、活动安排、报名流程、规章制度等）。
- FR-AI-QA-02 支持多轮对话，理解上下文语境，提供连贯的交互体验。
- FR-AI-QA-03 智能识别常见问题（FAQ），快速返回标准答案；对于复杂问题，引导用户找到相关负责人。

**3.8.2 个性化社团推荐 (FR-AI-REC)**
- FR-AI-REC-01 基于学生兴趣标签（科技、艺术、体育、公益等）进行社团匹配推荐。
- FR-AI-REC-02 分析学生技能特长（编程、设计、写作、组织能力等），推荐适合的社团岗位。
- FR-AI-REC-03 基于协同过滤算法，分析相似学生的社团选择，提供"志同道合"的社团推荐。

**3.8.3 智能助手交互界面 (FR-AI-UI)**
- FR-AI-UI-01 提供固定入口的聊天窗口（悬浮按钮或侧边栏），支持随时唤起。
- FR-AI-UI-02 支持快捷指令（如"推荐社团"、"我的活动"、"如何报名"）快速触发功能。
- FR-AI-UI-03 支持富媒体回复（卡片、图片、链接、按钮等），提升交互体验。
- FR-AI-UI-04 记录对话历史，用户可查看与AI的历史交互记录。

**3.8.4 AI模型与技术支持 (FR-AI-TECH)**
- FR-AI-TECH-01 采用大语言模型（LLM）如GPT、文心一言、通义千问等提供自然语言理解能力。
- FR-AI-TECH-02 构建校园社团领域知识库，进行RAG（检索增强生成）优化，提高回答准确性。
- FR-AI-TECH-03 确保AI输出内容安全合规，建立敏感词过滤与内容审核机制。

### 3.9 统计与报表 (FR-STAT)
- FR-STAT-01 系统管理员查看全局：社团总数、活跃度排名、招新转化率、活动参与度趋势。
- FR-STAT-02 社团管理员查看本社团内部：报名人数、录取率、活动参与率、成员流失率。
- FR-STAT-03 支持导出统计报表。

### 3.9 系统与审计 (FR-SYS)
- FR-SYS-01 记录敏感操作审计日志（登录、角色修改、录取决策）。
- FR-SYS-02 支持全局参数配置（附件大小限制、报名是否开放、公告审核开关）。

### 3.10 通用 (FR-COMMON)
- FR-COMMON-01 全局支持分页、排序与搜索。
- FR-COMMON-02 支持多条件过滤（时间范围、状态、标签）。

## 4. 非功能需求 (NFR)

### 4.1 性能 (NFR-PERF)
- NFR-PERF-01 常规查询接口 P95 延迟 < 400ms。
- NFR-PERF-02 支持至少 1000 并发学生同时提交招新报名（采用队列/限流保障）。

### 4.2 安全 (NFR-SEC)
- NFR-SEC-01 采用 HTTPS、JWT 加密签名；密码加密存储（BCrypt）。
- NFR-SEC-02 防护常见攻击：XSS、CSRF、SQL 注入、暴力破解（登录限速）。
- NFR-SEC-03 敏感字段（手机号、邮箱）在日志中脱敏。

### 4.3 可用性 (NFR-AVA)
- NFR-AVA-01 年度可用性 ≥ 99.5%。
- NFR-AVA-02 关键服务出现故障 30 分钟内可恢复（预案+监控报警）。

### 4.4 易用性 (NFR-UX)
- NFR-UX-01 表单设计简洁，移动端适配良好，三步内完成报名。
- NFR-UX-02 操作有明确反馈（加载、成功、失败提示）。
- NFR-UX-03 对话界面友好，支持快捷操作，AI回答清晰准确，提供可操作的建议。
- NFR-UX-04 推荐结果需附带推荐理由，用户可理解为何被推荐。

### 4.5 可维护性 (NFR-MAINT)
- NFR-MAINT-01 代码分层清晰（Controller-Service-Repository-Domain）。
- NFR-MAINT-02 关键模块单元测试覆盖率 ≥ 70%。

### 4.6 可扩展性 (NFR-SCALE)
- NFR-SCALE-01 支持分布式部署与水平扩展（Stateless 服务 + Redis）。

### 4.7 合规性 (NFR-COMP)
- NFR-COMP-01 遵循个人信息保护要求，用户可申请注销并清理数据。

## 5. 数据需求
- 需要保留完整的报名与审核历史（用于追溯）。
- 活动签到原始记录需保存至少 2 年。
- 审计日志保存周期不少于 1 年，可归档冷存储。

| **推荐引擎** | 协同过滤与个性化推荐 | 内部服务 / API | 可使用TensorFlow / PyTorch自建或第三方服务 |

## 7. 用例概述
1. 学生浏览社团 → 选择社团 → 查看招新批次 → 填报名表 → 等待审核 → 接收录取通知。
2. 社团管理员发布招新 → 审核报名 → 备注与评分 → 复审确定录取 → 批量发送通知 → 成员档案生成。
3. 社团管理员创建活动 → 设置报名 → 成员报名 → 活动进行扫码签到 → 结束后生成统计与总结。
4. 系统管理员查看统计 → 审核社团注册 → 冻结违规社团 → 导出报表。
5. 询问社团信息 → 获取个性化社团推荐 → 查看推荐理由 → 一键跳转报名。
6. 分析学生兴趣与技能 → 智能匹配合适社团 → 推送活动建议 → 提供参与路径。（可选）

## 8. 风险与缓解
| 风险 | 描述 | 等级 | 缓解策略 |
|------|------|------|----------|
| 并发报名峰值 | 开学季集中提交导致性能下降 | 高 | 排队 + 限流 + 缓存热点数据 |
| 数据合规 | 处理个人隐私数据需规范 | 中 | 最小化采集 + 数据脱敏 + 权限分层 |
| 内容审核 | 社团上传违规内容 | 中 | 关键词审核 + 管理员举报处理流程 |
| 需求膨胀 | 后期功能新增失控 | 中 | 版本规划 + 需求评审委员会 |
| AI模型准确性 | AI回答不准确或推荐不合理 | 中 | RAG知识库优化 + 人工审核机制 + 用户反馈循环 |
| AI成本控制 | LLM API调用成本过高 | 中 | 缓存常见问题答案 + 本地小模型处理简单问题 + 使用量监控 |
| AI安全风险 | AI生成违规或敏感内容 | 高 | 敏感词过滤 + 内容安全审核 + 输出后处理 |

## 9. 验收标准
- 核心功能（招新、活动、公告、成员管理）均可在测试环境端到端操作成功。
- **AI智能助理**能够准确回答至少90%的常见问题，推荐准确率达到70%以上。
- **个性化推荐系统**能够根据用户画像提供至少3个合理的社团/活动推荐。
- 性能压测达到并发指标。
- 安全扫描（SQL注入/XSS/弱口令）无高危问题。
- **AI内容安全**：无违规或敏感内容输出，敏感词过滤有效率100%。
- 文档齐全：需求、设计、API、部署、运维手册。
