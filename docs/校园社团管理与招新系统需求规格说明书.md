# 校园社团管理与招新系统 - 需求规格说明书

## 1. 引言

### 1.1 目的
本文档基于当前仓库的实际实现，描述系统已覆盖的业务范围、角色边界和功能需求，避免将未实现内容误写为现有能力。

### 1.2 目标
系统用于支持校园社团的统一展示、招新管理、活动运营、公告通知、资源申请、财务管理、审计与基础统计，并提供 AI 问答与推荐能力。

### 1.3 当前范围
当前版本实际覆盖：
- 用户注册、登录、刷新、登出、忘记密码
- 社团创建、查询、推荐、成员管理、解散流程
- 招新批次、表单字段、报名、审核、导出
- 活动管理、报名、签到、导出
- 公告与站内通知
- 资源申请与审批
- 财务流水与审批
- 审计日志与统计接口
- AI 智能问答与社团推荐

不作为当前已实现能力描述的内容：
- 小程序端
- CAS / OAuth2 统一认证接入
- 微信订阅消息
- 独立成员模块 `/api/members`
- MinIO、Kafka、ELK 等额外基础设施

## 2. 用户与权限

### 2.1 用户角色
当前项目中的权限体系分为两类：

#### 2.1.1 全局角色
- **游客**：未登录用户，可浏览公开社团、公告、活动等信息。
- **普通登录用户**：可更新个人信息、报名社团、报名活动、接收通知。
- **社团管理员**：具备某社团的管理能力，前端和部分接口会识别 `CLUB_ADMIN`。
- **系统管理员**：具备全局审批、删除、审计与统计访问能力，角色代码通常为 `ADMIN`。

#### 2.1.2 社团内部角色
在成员关系中通过 `roleCode` 表示，当前主要包括：
- `PRESIDENT`
- `MANAGER`
- `MEMBER`

### 2.2 权限说明
- 社团管理权限由 `PermissionService` 校验。
- 系统管理员可处理全局审批、用户状态与审计查询。
- 社团内部管理能力并非完全依赖单独的系统角色表述，而是结合成员关系与全局角色共同判断。

## 3. 功能需求

### 3.1 账号与认证
- 支持用户名密码登录。
- 支持 JWT 认证。
- 浏览器场景下通过 `HttpOnly Cookie` 承载 access token / refresh token。
- 支持 refresh token 刷新。
- 支持邮件验证码方式的忘记密码与重置密码。
- 支持登录失败限流。

### 3.2 社团管理
- 支持创建社团。
- 支持社团列表与社团详情查询。
- 支持基于用户身份的社团推荐。
- 支持查询“我的社团”。
- 支持社团成员新增、删除、导出、角色调整。
- 支持社团解散申请、撤回、恢复。

### 3.3 招新管理
- 支持创建招新批次。
- 支持为招新批次配置表单字段。
- 支持学生提交报名表。
- 支持初审与终审。
- 支持查询我的报名与批次报名数据。
- 支持导出报名结果。

### 3.4 活动管理
- 支持创建、更新、删除活动。
- 支持活动分页查询、详情查询、社团活动查询。
- 支持活动报名。
- 支持活动签到。
- 支持查询活动报名列表。
- 支持导出签到结果。

### 3.5 公告与通知
- 支持社团公告发布、列表查询、详情查询、删除。
- 支持站内通知列表查询、未读数查询、单条已读、全部已读。
- 支持通过 RabbitMQ 进行异步通知投递。

### 3.6 资源与财务
- 支持资源定义的新增、修改、删除、查询。
- 支持资源申请提交与审批。
- 支持财务流水提交、审批、驳回与余额查询。

### 3.7 统计与审计
- 支持系统统计与社团统计接口。
- 支持审计日志记录与查询。
- 支持 Prometheus 指标暴露。

### 3.8 AI 能力
- 支持基于知识库的社团问答。
- 支持社团推荐。
- 支持会话化聊天与基础频率限制。

## 4. 非功能需求

### 4.1 性能
- 常规查询接口应保持较低延迟。
- 高峰场景下通过 Redis、RabbitMQ 与分页查询降低系统压力。

### 4.2 安全
- 使用 BCrypt 存储密码。
- 使用 JWT 签名校验身份。
- 浏览器场景使用 HttpOnly Cookie 降低 token 被脚本直接读取的风险。
- 登录与敏感操作应保留审计记录。
- 对暴力登录尝试进行限流控制。

### 4.3 可维护性
- 代码按模块拆分，统一由 Maven 管理。
- 共享实体、仓储、公共能力集中在 `community-core`。
- AI 服务独立于 Java 主应用部署。

### 4.4 可扩展性
- 当前为模块化单体架构，可继续按领域拆分。
- 可继续扩展推荐算法、监控、部署自动化与前端交互。

## 5. 外部依赖
当前项目实际依赖：

| 依赖 | 作用 |
|------|------|
| MySQL | 业务主库 |
| Redis | token、验证码、限流等 |
| RabbitMQ | 异步通知 |
| 阿里云 OSS | 文件上传 |
| SMTP | 邮件验证码 / 密码重置 |
| DeepSeek API | LLM 能力 |
| Chroma | RAG 检索存储 |

不再将以下内容写为当前必备依赖：
- CAS / OAuth2 统一认证
- MinIO
- Kafka
- 微信订阅消息
- 第三方推荐引擎平台

---

## 6. 验收边界
当前项目验收应以仓库中真实存在的能力为准，重点关注：
- 后端接口可正常联调
- 前端页面可完成主要业务流程
- AI 问答与推荐接口可调用
- 审计、通知、资源、财务等模块可基本运行

不再将以下内容作为当前版本验收前提：
- 小程序端功能
- OAuth2 / CAS 单点登录
- 微信消息推送
- 独立 `/api/members` 模块
