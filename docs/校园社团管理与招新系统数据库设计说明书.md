# 校园社团管理与招新系统 - 数据库设计说明书

## 1. 引言

### 1.1 目的
本文档定义校园社团管理与招新系统的关系型数据库（MySQL）结构，包括概念模型、逻辑模型、各数据表字段说明、索引策略、约束与初始建表 SQL，作为开发与后续运维参考。

### 1.2 范围
覆盖业务主库（OLTP），不含数据仓库与离线分析层；缓存（Redis）、对象存储（MinIO/OSS）不在本文件详细展开。

---

## 2. 概念设计 (核心实体与关系)

实体：User、Role、Club、ClubTag、RecruitBatch、RecruitFormField、RecruitApplication、Member、Activity、ActivitySignup、ActivityAttendance、Notice、ResourceRequest、AuditLog、Attachment。

关系示意（文字 ER）：
```
User (1) --(1..*)--> RecruitApplication --(belongs to)--> RecruitBatch --(belongs to)--> Club
User (1) --(1..*)--> Member --(belongs to)--> Club
Club (1) --(1..*)--> Activity --(1..*)--> ActivitySignup --(1..*)--> ActivityAttendance
Club (1) --(1..*)--> Notice
Club (1) --(1..*)--> RecruitBatch
User (1) --(1..*)--> AuditLog
Club (1) --(1..*)--> ResourceRequest
```

---

## 3. 命名规范
- 表前缀统一：`t_`；多词使用下划线，例：`t_recruit_batch`。
- 主键统一 `id` BIGINT 自增。
- 审计字段：`created_at`, `updated_at`, `created_by`, `updated_by`。
- 逻辑删除（仅必要时）：`is_deleted` TINYINT(1)。

## 4. 逻辑模型与字段说明

## 5. 物理设计与存储引擎
- 统一使用 InnoDB；字符集 `utf8mb4`；排序规则 `utf8mb4_general_ci`。
- 时间字段不含时区，统一使用应用层处理（Asia/Shanghai）。
- 大型 TEXT/JSON 字段避免在高频列表查询中直接返回（可分表或拆分二级详情）。

---

## 6. 索引策略与原则
- 高频过滤条件建立联合索引（如 `club_id,status`）。
- 避免在低选择性字段（status 只有少量值）上建立单列索引除非频繁过滤。
- 通过慢查询日志与性能分析定期评估冗余索引。

## 7. 初始建表 SQL（部分示例）
```sql
CREATE TABLE `t_user` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  `username` VARCHAR(64) NOT NULL COMMENT '登录名',
  `password_hash` VARCHAR(255) NOT NULL COMMENT '密码哈希',
  `real_name` VARCHAR(64) NOT NULL COMMENT '真实姓名',
  `email` VARCHAR(128) DEFAULT NULL COMMENT '邮箱',
  `mobile` VARCHAR(32) DEFAULT NULL COMMENT '手机号',
  `status` VARCHAR(16) NOT NULL DEFAULT 'ACTIVE' COMMENT '状态',
  `last_login_at` DATETIME DEFAULT NULL COMMENT '最近登录',
  `created_at` DATETIME NOT NULL COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

CREATE TABLE `t_club` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '社团ID',
  `name` VARCHAR(128) NOT NULL COMMENT '名称',
  `short_name` VARCHAR(64) DEFAULT NULL COMMENT '简称',
  `category` VARCHAR(64) DEFAULT NULL COMMENT '分类',
  `logo_url` VARCHAR(255) DEFAULT NULL COMMENT 'Logo',
  `description` TEXT COMMENT '简介',
  `status` VARCHAR(16) NOT NULL DEFAULT 'PENDING' COMMENT '状态',
  `founded_year` INT DEFAULT NULL COMMENT '成立年份',
  `created_by` BIGINT NOT NULL COMMENT '创建人',
  `created_at` DATETIME NOT NULL COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_club_name` (`name`),
  KEY `idx_category_status` (`category`,`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='社团表';

CREATE TABLE `t_recruit_batch` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '批次ID',
  `club_id` BIGINT NOT NULL COMMENT '社团ID',
  `title` VARCHAR(128) NOT NULL COMMENT '标题',
  `description` TEXT COMMENT '说明',
  `start_time` DATETIME NOT NULL COMMENT '开始时间',
  `end_time` DATETIME NOT NULL COMMENT '结束时间',
  `quota` INT NOT NULL COMMENT '名额',
  `status` VARCHAR(16) NOT NULL DEFAULT 'DRAFT' COMMENT '状态',
  `created_at` DATETIME NOT NULL COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_club_status` (`club_id`,`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='招新批次';

CREATE TABLE `t_recruit_application` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '申请ID',
  `batch_id` BIGINT NOT NULL COMMENT '批次ID',
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `apply_data` JSON NOT NULL COMMENT '表单数据',
  `first_review_status` VARCHAR(16) NOT NULL DEFAULT 'PENDING' COMMENT '初审状态',
  `first_reviewer` BIGINT DEFAULT NULL COMMENT '初审人',
  `first_review_comment` VARCHAR(255) DEFAULT NULL COMMENT '初审意见',
  `final_review_status` VARCHAR(16) NOT NULL DEFAULT 'PENDING' COMMENT '复审状态',
  `final_reviewer` BIGINT DEFAULT NULL COMMENT '复审人',
  `final_review_comment` VARCHAR(255) DEFAULT NULL COMMENT '复审意见',
  `final_decision_at` DATETIME DEFAULT NULL COMMENT '最终时间',
  `created_at` DATETIME NOT NULL COMMENT '创建时间',
  PRIMARY KEY (`id`),
  KEY `idx_batch_user` (`batch_id`,`user_id`),
  KEY `idx_batch_final` (`batch_id`,`final_review_status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='招新申请';

CREATE TABLE `t_member` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '成员ID',
  `club_id` BIGINT NOT NULL COMMENT '社团ID',
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `role_code` VARCHAR(32) NOT NULL COMMENT '角色',
  `status` VARCHAR(16) NOT NULL DEFAULT 'ACTIVE' COMMENT '状态',
  `join_at` DATETIME NOT NULL COMMENT '加入时间',
  `points` INT NOT NULL DEFAULT 0 COMMENT '积分',
  `extra` JSON DEFAULT NULL COMMENT '扩展',
  PRIMARY KEY (`id`),
  KEY `idx_club_user` (`club_id`,`user_id`),
  KEY `idx_role` (`club_id`,`role_code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='成员表';

CREATE TABLE `t_activity` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '活动ID',
  `club_id` BIGINT NOT NULL COMMENT '社团ID',
  `title` VARCHAR(128) NOT NULL COMMENT '标题',
  `type` VARCHAR(32) DEFAULT NULL COMMENT '类型',
  `location` VARCHAR(255) DEFAULT NULL COMMENT '地点',
  `max_participants` INT DEFAULT NULL COMMENT '最大人数',
  `signup_start` DATETIME NOT NULL COMMENT '报名开始',
  `signup_end` DATETIME NOT NULL COMMENT '报名结束',
  `start_time` DATETIME NOT NULL COMMENT '开始时间',
  `end_time` DATETIME NOT NULL COMMENT '结束时间',
  `need_attendance` TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否签到',
  `status` VARCHAR(16) NOT NULL DEFAULT 'DRAFT' COMMENT '状态',
  `created_at` DATETIME NOT NULL COMMENT '创建时间',
  PRIMARY KEY (`id`),
  KEY `idx_club_status` (`club_id`,`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='活动';
```

## 8. 约束与一致性策略
- 外键可在逻辑层保证（高并发阶段避免性能折损），开发/测试环境可开启物理外键辅助验证。
- 使用事务保证单次复审操作的原子性。
- 使用唯一索引避免重复报名、重复签到。

---

## 9. 数据生命周期与归档
- 历史招新申请：超过 2 年可归档至历史表 `t_recruit_application_hist`。
- 审计日志：按月分区（`PARTITION BY RANGE (TO_DAYS(created_at))`）便于清理。
- 活动归档：活动结束后 30 天不再频繁访问，可迁移至归档库。

---

## 10. 安全与隐私
- 敏感字段（手机号、邮箱）访问分层；导出时需明确授权。
- 日志中禁止明文记录密码/令牌。
