# 校园社团管理与招新系统 - 数据库设计说明书

## 1. 引言

### 1.1 目的
本文档以 `community-core` 中的实体定义为准，说明当前项目实际使用的核心数据表与关系。

### 1.2 范围
覆盖当前项目中的关系型业务主库（MySQL）设计；不展开说明 Redis、RabbitMQ、OSS、Chroma 等非关系型存储。

---

## 2. 实际核心实体

当前代码中已存在的实体包括：

- `User`
- `Role`
- `Club`
- `Member`
- `RecruitBatch`
- `RecruitFormField`
- `RecruitApplication`
- `Activity`
- `ActivitySignup`
- `ActivityAttendance`
- `Notice`
- `NoticeRead`
- `Notification`
- `Resource`
- `ResourceApplication`
- `ClubFinance`
- `AuditLog`

以下内容不再作为当前已实现实体描述：
- `ClubTag`
- `Attachment`
- `ResourceRequest`（实际实现名称为 `ResourceApplication`）

---

## 3. 主要关系

```text
User --< t_user_role >-- Role
User --< Member >-- Club
Club --< RecruitBatch --< RecruitFormField
RecruitBatch --< RecruitApplication >-- User
Club --< Activity --< ActivitySignup >-- User
Activity --< ActivityAttendance >-- User
Club --< Notice
Notice --< NoticeRead >-- User
User --< Notification
Club --< ResourceApplication >-- Resource
Club --< ClubFinance
User --< AuditLog
```

---

## 4. 主要表说明

### 4.1 用户表 `t_user`
主要字段：
- `username`
- `password_hash`
- `real_name`
- `email`
- `mobile`
- `avatar_url`
- `interests`
- `status`

说明：用户角色通过中间表 `t_user_role` 维护。

### 4.2 角色表 `t_role`
主要字段：
- `code`
- `name`
- `description`

说明：当前项目中的全局角色以 `ADMIN`、`CLUB_ADMIN` 等为主，不再使用文档中原先的 `LEADER / OFFICER / MEMBER / ADMIN` 作为统一系统角色描述。

### 4.3 用户角色关联表 `t_user_role`
由 `User` 实体中的 `@ManyToMany` 关系自动映射：
- `user_id`
- `role_id`

### 4.4 社团表 `t_club`
主要字段：
- `name`
- `short_name`
- `category`
- `logo_url`
- `description`
- `status`
- `created_by`
- `visit_count`
- `balance`
- `dissolution_reason`
- `dissolution_date`

说明：当前项目中社团支持推荐、访问量统计、余额与解散流程等字段能力。

### 4.5 成员表 `t_member`
主要字段：
- `club_id`
- `user_id`
- `role_code`
- `status`
- `points`
- `join_at`
- `extra`

说明：当前成员角色实际以 `PRESIDENT`、`MANAGER`、`MEMBER` 等社团内部角色为主。

### 4.6 招新批次表 `t_recruit_batch`
主要字段：
- `club_id`
- `title`
- `description`
- `start_time`
- `end_time`
- `status`

### 4.7 招新表单字段表 `t_recruit_form_field`
主要字段：
- `batch_id`
- `field_name`
- `field_label`
- `field_type`
- `required`
- `options`

### 4.8 招新申请表 `t_recruit_application`
主要字段：
- `batch_id`
- `user_id`
- `form_data`
- `status`
- `first_review_comment`
- `final_review_comment`

### 4.9 活动表 `t_activity`
主要字段：
- `club_id`
- `title`
- `description`
- `location`
- `start_time`
- `end_time`
- `max_participants`
- `status`

### 4.10 活动报名表 `t_activity_signup`
主要字段：
- `activity_id`
- `user_id`
- `status`

### 4.11 活动签到表 `t_activity_attendance`
主要字段：
- `activity_id`
- `user_id`
- `checkin_time`
- `checkin_code`

### 4.12 公告表 `t_notice`
主要字段：
- `club_id`
- `title`
- `content`
- `publisher_id`

### 4.13 公告已读表 `t_notice_read`
主要字段：
- `notice_id`
- `user_id`
- `read_at`

### 4.14 站内通知表 `t_notification`
主要字段：
- `user_id`
- `title`
- `content`
- `type`
- `read_flag`

### 4.15 资源定义表 `t_resource`
主要字段：
- `name`
- `type`
- `description`
- `location`
- `capacity`
- `total_quantity`
- `status`

说明：资源类型区分场地与物资。

### 4.16 资源申请表 `t_resource_application`
主要字段：
- `club_id`
- `activity_id`
- `resource_id`
- `start_time`
- `end_time`
- `quantity`
- `description`
- `status`
- `applicant_id`
- `approver_id`

### 4.17 财务流水表 `t_club_finance`
主要字段：
- `club_id`
- `type`
- `amount`
- `description`
- `status`
- `applicant_id`
- `approver_id`

### 4.18 审计日志表 `t_audit_log`
主要字段：
- `user_id`
- `action`
- `resource_type`
- `resource_id`
- `detail`
- `ip`

## 5. 角色与状态说明

### 5.1 全局角色
由 `t_role` 管理，常见值：
- `ADMIN`
- `CLUB_ADMIN`
- 其他普通用户角色

### 5.2 社团内部角色
由 `t_member.role_code` 管理，常见值：
- `PRESIDENT`
- `MANAGER`
- `MEMBER`

### 5.3 业务状态
各模块状态值由代码维护，文档不再假设统一使用原先的 `LEADER / OFFICER / TRIAL / FINAL_PASS` 等所有枚举组合。

---

本文档已移除以下与实际代码不一致的内容：
- `ClubTag` 实体与相关关系
- `Attachment` 附件表

- 把成员角色统一描述为 `LEADER / OFFICER / MEMBER`
- 将资源与对象存储混为同一数据库实体的表述
