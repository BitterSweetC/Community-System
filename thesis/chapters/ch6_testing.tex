\chapter{系统测试}

\section{测试目标与方法}

本章测试目标是验证系统在“认证、权限、业务规则”上的实现有效性，并记录当前版本的可复现证据与剩余风险。需要强调的是，本章测试以阶段性工程验证为主，重点确认当前版本的可用性、主要性能边界与已暴露的问题，不等同于生产环境下的长期稳定性验证，也不构成严格意义上的大规模用户实验或公开 benchmark 评测。测试采用如下方法：
\begin{enumerate}
  \item \textbf{单元测试}：基于 JUnit 5 + Mockito，验证服务层关键逻辑；
  \item \textbf{前端流程验证}：基于 Playwright 复跑登录关键链路；
  \item \textbf{接口验证}：依据可直接复跑的 HTTP 请求检查核心接口流程；
  \item \textbf{安全检查}：验证未授权访问、越权访问、登录限频等安全行为；
  \item \textbf{稳定性检查}：通过异常路径和并发冲突场景验证业务幂等。
\end{enumerate}

  \item 当前自动化回归总计覆盖 6 个 Java 测试类、15 个后端用例与 1 条前端 Playwright 登录流程，主要集中在认证、角色变更与并发约束等关键路径；在此基础上，2026 年 3 月 16 日又补充完成了 1 轮请求级端到端 smoke 复跑，用于验证主要业务闭环；

\subsection{端到端业务链路复跑}

2026 年 3 月 16 日，本文在 Docker Compose 在线运行态重新生成一套 smoke 数据，并将结果留档于 \texttt{paper\_outputs/full-e2e-smoke/run-20260316-092834/}。本轮请求级复跑覆盖了认证全链路（注册、登录、改密、刷新、退出、找回密码、禁用用户令牌失效与恢复）、社团创建审批与成员管理、招新申请与评审、活动创建/报名/签到/导出/删除、系统公告与社团公告、站内通知读取、文件上传、资源申请审批、财务审批、审计日志、AI 聊天、社团解散/恢复/强制解散以及用户退社等关键业务闭环。

这轮复跑表明，当前版本在单机容器环境下已经具备主要功能的可复现端到端运行能力；同时也暴露出若干需要在论文中如实表述的实现语义，例如管理员“删除社团”当前属于状态迁移到 \texttt{DISSOLVED} 的软删除语义，成员移除与退社则通过 \texttt{LEFT} 状态保留历史关系。因此，本节证据更适合支撑“当前原型系统可运行、可复跑、主要业务链路可闭环”的工程结论，而不应外推为长期稳定性、生产级可靠性或完整用户验收结论。

\subsection{业务幂等与并发验证}

在活动报名、活动签到、招新终审、资源审批、财务审批等路径中，系统均引入了“唯一约束 + 业务状态校验 + 悲观锁”组合机制。本轮除 JMeter 写接口脚本外，还复跑了 \texttt{FinanceServiceImplConcurrencyTest}、\texttt{ResourceServiceImplConcurrencyTest} 与 \texttt{ActivityServiceImplConcurrencyTest}，三项并发测试均通过。结合 300 并发报名与签到脚本在本轮均保持 0\% 错误率，可以说明当前版本对核心写路径已具备一定并发保护能力，但更高并发、长稳运行与真实多用户竞争场景仍需继续补测。

  \item 在当前脚本下，登录、社团列表热缓存查询、活动报名与活动签到四类核心业务接口均未出现错误，说明非 AI 业务链路在本轮单节点补测中表现稳定；
  \item 社团列表查询的 6.24ms 平均响应时间仅对应热缓存场景，不能直接外推为冷缓存、缓存失效或数据规模进一步扩张后的表现；

\end{enumerate}

\subsubsection{覆盖边界与未覆盖项}

需要说明的是，本轮补测主要覆盖短时并发脚本，并未执行持续 30 分钟的长稳压测，也未对 CPU、内存、连接池等资源指标进行系统化时间序列记录。因此，本文不再报告“30 分钟持续压测资源使用情况”等定量结论；相关内容需在后续结合 Prometheus 指标与更长时间的 soak test 单独补做。

\subsection{性能现象与优化启示}

本轮补测未设计“关闭缓存”或“取消索引/锁策略”的 A/B 对照脚本，因此本文不再给出“优化前/优化后提升百分比”的定量表述。结合接口实现与压测现象，可归纳出以下工程启示：

\begin{enumerate}
  \item 社团列表在热缓存场景下平均响应时间仅为 6.24ms，说明 Redis 缓存在重复读取场景中对降低查询时延具有明显作用；
  \item 报名与签到写接口虽然涉及数据库写入、状态校验与并发控制，但在当前 300 并发脚本下仍保持了较低延迟和 0\% 错误率，说明现有业务锁与唯一约束策略具备一定工程可行性；
  \item AI 问答链路的高延迟与高超时率已成为整体体验短板，后续优化重点应放在外部模型调用、超时配置、流式返回与降级兜底策略上，而非继续夸大其当前吞吐表现。
\end{enumerate}

\subsection{AI 功能阶段性评估}

在解释 AI 模块结果前，需要说明：本节评估主要服务于工程可用性验证，题集、基线与样例场景均来源于当前项目环境，文中暂未给出公开 benchmark、多评审者一致性标注或在线 A/B 试验流程。因此，以下结果仅反映当前版本在既定知识库和样例数据下的阶段性表现，不宜直接外推为具有普适性的学术结论，也不构成可替代标准评测流程的独立证据。

其中，可直接复现的在线链路与性能工件已在附录中统一挂载；200 题人工核验目前仍仅保留聚合统计，仓库内尚未包含逐题判定表与题集原文。相较之下，2026 年 3 月 13 日补充完成的推荐模式对比已经保留 \texttt{compare\_summary}、\texttt{summary\_records}、\texttt{ranking\_records} 与统一口径的 \texttt{ranking\_records\_top5} 等机器可读记录，可用于复现本节推荐部分的同批用户横向比较。即便如此，由于当前仍缺少相关性人工标注、点击/转化日志与在线 A/B 试验，本节结果仍应被理解为阶段性工程观察，而非可直接外推的算法优越性结论。

\subsubsection{推荐策略阶段性观察}

\begin{enumerate}

  \item 由于当前仍缺少显式相关性标签、点击日志与在线转化数据，本轮对比只能支持“可返回、可比较、结构有差异”的工程结论，尚不能据此宣称 hybrid 在推荐质量上优于 cf 或 cb。
\end{enumerate}

\section{测试结论与改进建议}

\subsection{当前测试结论}

\begin{enumerate}
  \item 本轮自动化复跑中，6 个后端测试类共 14 个用例与 1 条前端 Playwright 登录流程均已通过，说明关键回归路径在当前版本中具备基本可复现性；
  \item 鉴权烟测显示，未登录访问受保护接口返回 403，普通用户访问管理员监控端点返回 403，而管理员访问同一端点返回 200，说明所选代表性权限边界在当前版本下有效；但该结论仅覆盖权限边界烟测，不等同于完整安全测评；
  \item 并发测试与 300 并发写接口脚本均未发现重复写入导致的接口错误，表明当前版本对核心写路径具备一定并发保护能力；
  \item JMeter 补测为当前单节点环境建立了新的阶段性性能基线，但该基线仅对应既定脚本与当前数据规模，尚不能替代长期运行验证与多实例场景评估；
  \item AI 模块在内部问答核验与同批 300 用户的推荐模式对比中均表现出一定原型可用性；其中 cf、cb 与 hybrid 三种推荐模式均实现 300/300 成功和非空返回，平均耗时分别为 273.02ms、276.88ms 与 280.46ms；但 AI 问答链路仍存在明显时延与超时问题，且 200 题结果目前仅有聚合统计，推荐模块也仍缺少带标签的相关性验证与在线行为证据，因此该部分结论应限定为阶段性工程观察。
\end{enumerate}

\subsection{改进建议}

\begin{enumerate}
  \item 统一维护测试基线，业务逻辑变更时同步更新测试桩；
  \item 将当前关键用例纳入 CI 流水线，防止回归问题长期累积；
  \item 增补集成测试（含 MySQL/Redis/RabbitMQ）以验证真实依赖交互；
  \item 增加性能压测脚本与基线数据，形成可追踪的性能演进记录；
  \item 为 AI 模块补充标准化评估协议，包括题集构建规范、人工标注一致性要求以及推荐实验脚本。
\end{enumerate}
