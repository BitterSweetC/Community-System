\section{单元测试}

针对核心Service层与工具类编写单元测试，使用Mockito模拟Repository依赖，确保业务逻辑的正确性。

\begin{lstlisting}[language=Java, caption=ClubService单元测试示例]
@ExtendWith(MockitoExtension.class)
class ClubServiceTest {

    @Mock
    private ClubRepository clubRepository;

    @InjectMocks
    private ClubServiceImpl clubService;

    @Test
    void createClub_shouldSaveAndReturnClub() {
        ClubCreateRequest req = new ClubCreateRequest("测试社团", "文艺", "简介");
        Club saved = Club.builder().id(1L).name("测试社团").build();
        when(clubRepository.save(any())).thenReturn(saved);

        ClubDTO result = clubService.createClub(req, 1L);

        assertThat(result.getId()).isEqualTo(1L);
        verify(clubRepository, times(1)).save(any());
    }

    @Test
    void approveClub_withInvalidStatus_shouldThrow() {
        Club club = Club.builder().id(1L).status(ClubStatus.ACTIVE).build();
        when(clubRepository.findById(1L)).thenReturn(Optional.of(club));

        assertThatThrownBy(() -> clubService.approveClub(1L, true))
            .isInstanceOf(BusinessException.class)
            .hasMessageContaining("状态");
    }
}
\end{lstlisting}

\section{测试结果分析}

经过全面测试，系统各项功能运行稳定，主要结论如下：

\begin{enumerate}
  \item 所有核心功能接口测试通过率100\%，异常场景均能正确处理并返回规范错误信息；
  \item 安全防护机制有效，登录限流、Token黑名单、权限控制均按预期工作；
  \item 在100并发用户场景下，核心接口响应时间满足200ms以内的设计要求；
  \item Redis缓存策略显著提升了高频查询接口的性能表现。
\end{enumerate}
