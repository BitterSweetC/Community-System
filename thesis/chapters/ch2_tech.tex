\chapter{相关技术介绍}

本章对通用校园社团管理系统使用的相关技术进行介绍，内容包括后端思想、前端技术、中间件等。

\section{后端技术栈}

\subsection{Spring Boot 3.x 与模块化单体}

Spring Boot 是 Spring 生态中用于快速构建独立应用程序的框架。它强调自动配置与“约定优于配置”的工程理念，能够在一定程度上减少项目初始化与组件集成时的样板代码\cite{springboot_docs}。

本系统后端基于 Spring Boot 3.2.0 与 JDK 21 开发，采用 Maven 多模块组织方式。业务代码按领域拆分为 \texttt{community-user}、\texttt{community-club}、\texttt{community-activity}、\texttt{community-recruit}、\texttt{community-notice}、\texttt{community-admin} 等模块，并由 \texttt{community-gateway} 统一聚合启动。

模块化单体架构的核心优势在于：
\begin{enumerate}
  \item 开发调试成本低，无需启动多个独立进程；
  \item 跨模块事务处理简单，可直接使用本地事务；
  \item 通过明确的模块边界支持后续服务拆分；
  \item 部署运维简单，仅需管理单一应用实例。
\end{enumerate}

这一方案在保持单体部署简洁性的同时，保留了清晰的模块边界，便于后续演进为微服务架构；其工程取舍与模块化单体强调的“先控制复杂度、再按需拆分”思路一致\cite{microservices2015,microservices_patterns2018}。

\subsection{Spring Security 6 + JWT + Redis 会话校验}

Spring Security 是一个功能强大且高度可定制的身份验证与访问控制框架，在 Spring 应用安全体系中占据核心位置。它提供了身份验证、授权以及常见 Web 安全防护等能力\cite{spring_security2020}。

系统安全框架使用 Spring Security 6，认证凭据采用 JWT（JSON Web Token）\cite{jwt_rfc}。JWT 是一种开放标准（RFC 7519），它定义了一种紧凑且自包含的方式，用于在各方之间作为 JSON 对象安全地传输信息。

与仅做“无状态验签”不同，本系统还将登录态写入 Redis，并在过滤器中二次校验令牌是否仍在服务端会话中，从而实现“可主动失效”的会话控制。这种设计试图结合 JWT 的无状态优势与传统会话管理的可控性，也借助内存型键值存储支撑高频会话校验场景\cite{redis_docs}。

认证流程的关键点如下：
\begin{enumerate}
  \item 登录成功后签发 Access Token 与 Refresh Token；
  \item Access Token 与 Refresh Token 均通过 HttpOnly Cookie 下发，前端通过 \texttt{withCredentials} 自动携带；
  \item Access Token 默认有效期为 1 小时，Refresh Token 默认有效期为 24 小时；
  \item Access Token 同步写入 Redis 键 \texttt{auth:token:*}，请求到达时先验签再验 Redis；
  \item 登出时删除 Redis 中对应键，并清除 Cookie，实现即时下线。
\end{enumerate}

此外，系统对登录接口实现了基于 Redis 的失败计数限流（15 分钟窗口内超过 10 次失败将被限制），用于降低暴力破解风险。这种机制有助于减少恶意尝试持续撞库或暴力破解带来的安全压力。

\subsection{Spring Data JPA + MySQL 8}

Spring Data JPA 是 Spring 框架提供的数据访问抽象层，它基于 JPA（Java Persistence API）规范，通过面向对象的方式操作关系型数据库。其较明显的优势在于能够简化数据访问层代码：开发者只需定义接口并遵循命名约定，框架即可生成常见 CRUD 操作的实现，从而减少重复样板代码\cite{jpa2022}。

本系统持久层采用 Spring Data JPA，实体类统一定义于 \texttt{community-core} 模块，以保持数据模型在各业务模块间的一致性。在高并发写场景（如活动报名、签到、招新终审、资源审批、财务审批）中，系统通过悲观锁（\texttt{PESSIMISTIC\_WRITE}）尽量保证关键事务的一致性，避免重复提交与并发覆盖问题。悲观锁机制在事务开始时即对数据行加锁，直到事务提交才释放，因此更适合用于需要优先控制并发冲突的业务路径\cite{jpa2022}。

MySQL 8.0 作为系统主数据库，承担用户、社团、成员、活动、招新、公告与通知、财务、资源等核心数据存储。MySQL 8.0 相比早期版本引入了诸多改进，包括默认字符集改为 utf8mb4、对 JSON 类型的持续支持以及窗口函数能力等，这些特性为系统提供了更强的数据处理能力和更好的国际化支持\cite{mysql_docs}。

\subsection{Redis、RabbitMQ 与对象存储}

系统引入多种中间件与云服务以支撑高性能与异步处理需求：

\begin{enumerate}
  \item \textbf{Redis}：Redis 是一个开源的内存数据结构存储系统，支持字符串、哈希、列表、集合等多种数据类型。本系统使用 Redis 7 作为缓存与会话存储中间件，主要应用场景包括：认证会话管理（存储 JWT 令牌与用户会话信息）、登录失败计数限流（15 分钟窗口内超过 10 次失败将被限制）等高频键值读写操作。Redis 的内存数据结构特性使其适合承载高频键值访问场景，有助于降低数据库压力并提升系统响应速度\cite{redis_docs}。

  \item \textbf{RabbitMQ}：RabbitMQ 是一个开源消息代理中间件，可用于队列化消息传递与异步处理。本系统使用 RabbitMQ 3.12 实现站内通知的异步分发机制：业务模块（如社团审批、活动报名、招新审核等）在关键操作完成后发布消息到消息队列，通知模块作为消费者异步接收消息并落库，前端通过轮询接口读取通知变化。这种解耦设计使得业务操作与通知发送互不阻塞，并为后续扩展留出接口空间\cite{rabbitmq_docs}。

  \item \textbf{阿里云 OSS}：阿里云对象存储服务（Object Storage Service）是一种海量、安全、低成本、高可靠的云存储服务。本系统使用 OSS 存储用户头像、活动封面、社团 Logo 等静态文件资源。文件上传后生成外链 URL 并存储于数据库，前端通过 URL 直接访问 OSS 资源，避免了文件流量经过应用服务器，降低了服务器带宽压力并提升了文件访问速度。
\end{enumerate}

\subsection{WebSocket 与可观测性}

WebSocket 是一种在单个 TCP 连接上进行全双工通信的协议，相比传统的 HTTP 轮询方式，它能够支持服务端主动推送消息，减少频繁轮询带来的额外请求开销。本系统使用 Spring WebSocket 结合 STOMP（Simple Text Oriented Messaging Protocol）协议与 SockJS（WebSocket 降级方案）构建实时消息能力\cite{websocket_realtime}。典型应用场景是活动签到人数实时广播：当有学生完成签到时，服务器通过 WebSocket 主动推送最新签到人数给所有在线的活动管理员，实现数据的实时同步。

可观测性方面，系统依托 Spring Boot Actuator 暴露 Prometheus 指标端点（\texttt{/actuator/prometheus}）。Prometheus 是一个开源的监控与告警系统，通过定时抓取应用暴露的指标数据，实现对系统运行状态的持续观测\cite{prometheus_docs}。本系统配置 Prometheus 每 15 秒抓取一次指标数据，并使用 Grafana 完成可视化监控看板。结合 Micrometer 业务埋点，系统可观测登录成功/失败计数、活跃社团数量、待审批资源数量等关键业务指标，为系统运维与性能优化提供数据支持。

\section{前端技术栈}

\subsection{Vue 3 + Vite + Element Plus}

Vue 3 是目前较主流的渐进式 JavaScript 框架之一，相比 Vue 2 引入了 Composition API、更好的 TypeScript 支持以及若干性能优化特性。Composition API 通过函数式编程风格组织组件逻辑，使代码在复用与维护方面更灵活\cite{vue3docs}。

本系统前端基于 Vue 3 构建单页应用（SPA），构建工具使用 Vite。Vite 利用浏览器原生 ES 模块支持，在开发环境下通常能够提供较快的冷启动速度与热模块替换（HMR）体验，相比传统的 Webpack 构建方式，更适合当前项目的前端开发节奏。

UI 组件库方面，管理端与学生端页面统一采用 Element Plus 组件体系。Element Plus 是专为 Vue 3 设计的桌面端组件库，提供了表格、表单、对话框、导航菜单等较丰富的开箱即用组件，使系统在保持开发效率的同时，也较容易维持管理端与学生端界面风格的一致性。

\subsection{Pinia 状态管理与路由权限守卫}

Pinia 是 Vue 3 官方推荐的状态管理库，作为 Vuex 的继任者，它提供了更简洁的 API、更好的 TypeScript 支持以及模块化的状态管理方案。Pinia 通过 Store 概念集中管理应用的全局状态，使得跨组件的数据共享与状态同步变得简单高效。

本系统通过 Pinia 管理认证态与用户信息。在当前实现中，前端本地仅保存“已认证标记”与用户对象（包含用户 ID、用户名、角色等基本信息），真实的 JWT 令牌由浏览器通过 HttpOnly Cookie 托管，JavaScript 代码无法直接访问，这有助于降低 XSS 场景下令牌被直接窃取的风险。

路由层通过 Vue Router 的全局前置守卫（beforeEach）实现访问控制：当用户尝试进入 \texttt{/admin}（系统管理员页面）或 \texttt{/clubadmin}（社团管理员页面）等受保护路由时，守卫会先调用后端接口刷新用户信息并校验角色权限，只有具备相应角色的用户才能访问对应页面，否则将被重定向至登录页或无权限提示页。这种前端路由守卫与后端权限校验相结合的方式，在提升用户体验的同时，也能形成一层较直接的界面访问限制。

\subsection{Axios 通信策略}

Axios 是一个基于 Promise 的 HTTP 客户端库，支持浏览器与 Node.js 环境，提供了请求拦截、响应拦截、请求取消等强大功能。相比原生的 fetch API，Axios 提供了更友好的错误处理机制与更丰富的配置选项。

本系统创建统一的 Axios 实例并设置 \texttt{withCredentials=true}，以支持跨域请求时自动携带 Cookie。这一配置使得前端在调用后端 API 时，浏览器会自动将 HttpOnly Cookie 中的 JWT 令牌随请求发送，无需前端手动管理令牌。

响应拦截器对后端统一返回结构（\texttt{\{code, message, data\}}）进行解包处理：当响应状态码为 200 且业务代码 code 为成功时，直接返回 data 字段给调用方；当遇到 401（未认证）或 403（无权限）错误时，拦截器自动触发前端会话清理（清除 Pinia 中的用户状态）并重定向至登录页，避免在每个 API 调用处重复编写错误处理逻辑。这种统一的通信策略减少了前端重复代码，也更便于后续维护。

\section{AI 智能服务技术}

\subsection{FastAPI 智能服务网关}

FastAPI 是一个现代化的 Python Web 框架，基于标准 Python 类型提示构建，具有开发门槛相对较低、接口定义清晰以及自动生成 API 文档等特点。它通常被认为具有较好的性能表现，这与其底层使用 Starlette 作为 Web 框架、使用 Pydantic 进行数据验证有关\cite{fastapi2020}。

本系统的 AI 服务独立于 Java 主服务部署，使用 FastAPI 提供 RESTful 接口。这种拆分方式便于后续对 AI 能力单独扩展、调试与替换，也尽量减少对主业务系统稳定性的直接影响。AI 服务暴露的核心端点包括：

\begin{enumerate}
  \item \texttt{POST /chat}：社团知识问答接口，接收用户提问并返回基于知识库的智能回答；
  \item \texttt{POST /recommend}：个性化社团推荐接口，根据用户历史行为与兴趣标签推荐合适的社团；
  \item \texttt{POST /sync}：知识库补充接口，接收新增文本内容及来源信息，并将其写入本地向量库；
  \item \texttt{GET /health}：健康检查接口，用于监控服务运行状态。
\end{enumerate}

FastAPI 自动生成的交互式 API 文档（基于 Swagger UI）为开发与测试提供了便利，开发阶段可以直接在浏览器中对各个接口进行检查。

\subsection{LangChain Agent + RAG}

LangChain 是一个用于开发大语言模型应用的开源框架，提供模型接口抽象、工具调用、Agent 组织等能力，可用于构建带检索、工具调用与多步骤推理能力的应用\cite{langchain_docs}。

本系统的问答链路采用 LangChain Agent 组织工具调用与检索增强流程。检索增强生成（RAG，Retrieval-Augmented Generation）是一种结合信息检索与生成式 AI 的技术范式\cite{lewis2020rag,rag_applications2023}：系统首先从知识库中检索与用户问题相关的文档片段，然后将这些片段作为上下文提供给大语言模型，使模型能够基于真实数据生成准确的回答，有效缓解了大模型的"幻觉"问题。在当前实现中，针对公告、活动、招新、资源、财务等高确定性问题，系统还会优先调用封装好的业务工具查询实时数据，而不是一律依赖向量检索。

知识库向量存储采用 Chroma，这是一个开源的嵌入式向量数据库\cite{chroma2023}。当前版本主要从项目目录下的知识文件加载文本内容，经过文档切分后，通过嵌入模型转换为向量并写入本地持久目录。推理模型接入 DeepSeek 兼容接口；当向量检索不可用时，系统提供降级回答路径，优先返回带边界说明的谨慎回答，以保证服务的可用性。嵌入层通过本地封装的创建函数进行初始化，默认使用 \texttt{all-MiniLM-L6-v2}，并在依赖不可用时回退为本地哈希向量表示。

\subsection{混合推荐算法}

推荐系统是现代互联网应用的核心技术之一，旨在根据用户的历史行为与偏好，为用户推荐可能感兴趣的内容。本系统的推荐模块采用”协同过滤 + 语义内容”融合策略，结合了两种经典推荐算法的优势\cite{collaborative_filtering2009,recommendation_hybrid2002}。

协同过滤侧使用 TruncatedSVD（截断奇异值分解）对用户-社团交互矩阵进行分解\cite{svd_recommend,collaborative_filtering2009}。该算法通过矩阵分解技术挖掘用户与社团之间的隐含关系：将高维稀疏的交互矩阵分解为低维稠密的用户特征矩阵与社团特征矩阵，从而发现具有相似兴趣的用户群体以及具有相似属性的社团群体。这种方法能够有效处理数据稀疏性问题，挖掘出用户可能感兴趣但尚未接触过的社团。

内容侧依据社团文本向量（由社团名称、简介、类别等文本信息通过嵌入模型生成）与用户历史偏好构建相似度分数。通过计算用户历史加入社团的文本向量与候选社团文本向量之间的余弦相似度，可以找到与用户兴趣相匹配的社团。

最终通过加权融合得到候选排序结果：协同过滤分数与内容相似度分数按一定权重相加，综合考虑用户行为模式与内容相关性\cite{recommendation_hybrid2002}。在冷启动情况下（新用户无历史行为数据），系统回退至按社团热度（访问量、成员数等指标）排序，确保推荐功能的可用性。

\section{部署与运维技术}

\subsection{Docker Compose 编排}

Docker 是一种容器化技术，通过将应用及其依赖环境打包为轻量级、可移植的容器，解决了"在我机器上能运行"的经典问题。Docker Compose 是 Docker 官方提供的容器编排工具，通过 YAML 配置文件定义多容器应用的服务、网络、数据卷等资源，实现一键启动整个应用栈。

本系统使用 Docker Compose 管理多容器协作\cite{docker_cloud}，编排的服务包括：MySQL 8.0 数据库、Redis 7 缓存、RabbitMQ 3.12 消息队列、Spring Boot 应用容器、Vue 前端容器、FastAPI AI 服务容器、Prometheus 监控服务以及 Grafana 可视化平台。所有服务通过 Docker 网络互联，数据通过数据卷持久化。

这种容器化部署方案带来了多重优势：首先，开发环境与生产环境保持高度一致，降低了因环境差异导致的部署问题；其次，各服务的依赖版本被固化在镜像中，避免了版本冲突；最后，通过 \texttt{docker-compose up -d} 命令即可一键启动所有服务，通过 \texttt{docker-compose down} 命令一键停止并清理资源，极大简化了部署与运维流程。

\subsection{Prometheus + Grafana}

Prometheus 是一个开源的系统监控与告警工具，采用时间序列数据库存储指标数据，支持多维数据模型与强大的查询语言 PromQL。Prometheus 通过"拉取"模式工作：定时向目标应用发起 HTTP 请求，抓取暴露的指标数据并存储。这种设计使得监控系统与被监控应用解耦，应用只需暴露指标端点即可。

本系统配置 Prometheus 定时抓取后端 \texttt{/actuator/prometheus} 指标端点，抓取间隔为 15 秒。Spring Boot Actuator 自动暴露了 JVM 内存使用、线程数、HTTP 请求统计等基础指标。结合 Micrometer 业务埋点，系统还暴露了登录成功/失败计数、活跃社团数量、待审批资源数量等关键业务指标。

Grafana 是一个开源的数据可视化与监控平台，支持多种数据源（包括 Prometheus、MySQL、InfluxDB 等）。Grafana 通过连接 Prometheus 数据源，使用 PromQL 查询指标数据，并通过丰富的图表类型（折线图、柱状图、仪表盘等）构建监控看板。运维人员可以通过 Grafana 实时查看系统运行状态、性能指标与业务数据，及时发现异常并进行处理。Grafana 还支持告警规则配置，当指标超过阈值时自动发送告警通知，为系统的稳定运行提供保障。
