\chapter{总结与展望}

\section{工作总结}

这篇论文围绕高校社团管理数字化需求，完成了一套基于 Spring Boot 的模块化单体系统的设计、实现与测试验证。综合全文结果可以看到，系统已能支撑社团管理中的主要业务流程，并在当前原型版本中实现了社团范围内成员积分档案、按角色聚合的统一待办中心和实时运营看板（实时大屏）等辅助运营能力，且已完成页面与接口对应关系的运行态核对；在功能完整性、安全机制以及非 AI 核心链路性能方面都具备了较好的实现基础，AI 问答与推荐模块也在当前版本中体现出一定的辅助智能服务能力。与此同时，AI 问答链路仍存在比较明显的时延瓶颈。因此，这篇论文更适合被看作一次面向高校社团管理场景的原型系统设计与实现研究，说明系统已具备基本可用性，但距离成熟系统仍有进一步完善空间。

\subsection{对研究问题的回答}

结合全文设计、实现与测试结果，这篇论文对绪论中提出的研究问题作出如下回答：

\begin{enumerate}
  \item \textbf{模块化单体架构对社团全生命周期业务的支撑能力}：从系统实现与联调结果看，模块化单体方案已能承载用户、社团、活动、招新、公告通知、资源、财务与 AI 服务等核心业务模块，说明该架构在当前单节点原型场景下具有较好的工程可行性。至于其扩展性表现，目前更多还是基于现有实现与部署经验作出的判断，后续还需要结合多实例、长期运行和更大规模负载进一步观察。
  \item \textbf{认证机制与协同通知机制的可用性}：结合权限行为验证、接口联调与并发脚本结果，JWT、HttpOnly Cookie 与 Redis 会话校验的组合机制可以完成会话控制与主动失效，WebSocket/RabbitMQ 协同机制也能支撑签到广播与异步通知等典型场景。这说明这篇论文设计的认证与通知方案在当前原型系统中是可用的。与此同时，浏览器外客户端在 \texttt{/api/auth/refresh} 的补测中仍观察到 \texttt{refresh\_token} 传递兼容性现象，因此现有验证仍主要集中在权限边界和关键链路冒烟测试，距离完整的安全测评和生产级实时系统评估还有差距。
  \item \textbf{RAG 问答与推荐模块的可用性}：从项目内部问答核验、300 名测试用户的推荐模式对比以及在线脚本结果来看，RAG 问答与推荐模块在原型层面表现出一定可用性。其中 cf、cb 与 hybrid 三种推荐模式均实现了 300/300 成功且全部返回非空结果，平均时延分别为 238.20ms、237.11ms 和 238.36ms，说明当前实现下推荐结果能够稳定返回，且融合策略确实改变了排序结构。另一方面，AI 问答链路仍存在高时延和高超时率；问答题集原文与逐题判定表尚未补齐，推荐相关性标注与点击/转化日志也仍不足。因此，这部分结果更适合作为原型阶段验证：其中问答聚合准确率（如 87.5\%）目前仅作为内部观察值，不作为可独立复算的对外指标。
\end{enumerate}

\subsection{主要工作成果}

\subsubsection{功能完整性}

系统实现了覆盖社团全生命周期的八大功能模块，包括：

\begin{enumerate}
  \item \textbf{用户管理模块}：实现用户注册、登录、权限管理、个人信息维护等功能，支持基于角色的访问控制（RBAC）；
  \item \textbf{社团管理模块}：实现社团创建申请、审批、成员管理、生命周期管理（从 PENDING 到 DISSOLVED）等功能；
  \item \textbf{活动管理模块}：实现活动发布、报名、签到码生成与核验、签到记录导出、WebSocket 实时广播等功能；
  \item \textbf{招新管理模块}：实现招新批次管理、动态表单配置、多阶段审核（初审/终审）、名额控制等功能；
  \item \textbf{公告与通知模块}：实现公告发布、站内通知异步分发（RabbitMQ）、前端轮询读取、未读统计等功能；
  \item \textbf{财务管理模块}：实现财务收支记录、审批流程、余额管理、流水查询等功能；
  \item \textbf{资源管理模块}：实现场地与设备资源申请、时段冲突检测、库存校验、审批流程等功能；
  \item \textbf{AI 智能服务模块}：实现基于 RAG 的知识库问答、混合推荐算法，以及知识库初始化与手动补充入口等功能。
\end{enumerate}

当前版本围绕 21 张数据表组织主要业务领域，并实现了百余个后端 REST API 接口，形成了较完整的前后端与 AI 服务原型。

在上述主模块之外，当前版本还补充了社团范围内成员积分档案、按角色聚合的统一待办中心与实时运营看板页面等辅助能力，用来支撑成员激励、待审事项聚合与运行态观察。

\subsubsection{架构与实现特点}

\begin{enumerate}
  \item \textbf{模块化单体架构}：通过 Maven 多模块组织、明确的模块边界与依赖管理，在保持单体应用部署简便性的同时，实现了业务模块的高内聚低耦合，更适合中小型高校场景下的部署与演进；

  \item \textbf{混合认证机制}：结合 JWT 双令牌、HttpOnly Cookie 与 Redis 会话校验，实现了“无状态验签 + 可主动失效”的混合认证方案。该方案既保留了 JWT 的无状态优势，又通过 Redis 二次校验实现了会话的主动失效能力，同时利用 HttpOnly Cookie 降低令牌被脚本直接读取的风险；

  \item \textbf{实时异步协同通知架构}：针对不同场景的差异化需求，设计了分层通知架构。关键实时场景（活动签到）采用 WebSocket 主动推送，非关键通知场景采用 RabbitMQ 异步分发 + 前端轮询读取，有效平衡了实时性与系统吞吐；

  \item \textbf{社团边界内的成员激励与运营辅助设计}：系统没有设计全站统一积分账户，而是将成员积分绑定到社团成员关系，并结合积分流水、活动奖励结算与人工调分形成可回溯的激励模型；同时，通过统一待办聚合接口和实时运营看板统计接口收敛管理侧的待审口径与核心运营指标，减少多页面重复统计和手动切换成本；

  \item \textbf{RAG 增强的知识问答}：系统把 RAG 放到高校社团管理场景中，采用“规则路由 + 业务工具 + 检索增强 + 提示词编排”的 LangChain 组件化链路，并配合 Chroma 向量库实现问答。回答阶段会结合用户上下文和文档可见性控制边界。项目内部自建 200 题题集的聚合人工核验显示，该模块已经有一定可用性；但仓库里还没有逐题判定表和题集原文，评估流程还需要进一步标准化；

  \item \textbf{混合推荐与冷启动兜底策略}：系统融合了 SVD 协同过滤和语义内容推荐，并在新用户场景下加入热门社团回退机制，保证无历史行为时推荐也能正常返回。当前实现还加入了行为权重与时间衰减，并支持 \texttt{cf/cb/hybrid} 三种模式切换。在同一批 300 个测试用户上的模式对比中，cf、cb 与 hybrid 都达到 300/300 成功且非空返回；hybrid 的平均耗时为 238.36ms，统一 Top-5 口径下的排序结构位于 cf 与 cb 之间，说明融合逻辑确实改变了排序结果，不是简单退化成单一模式。不过，这部分结果更适合说明可返回性与排序差异，而不是直接证明推荐质量更优。
\end{enumerate}

\subsubsection{性能与质量保障}

\begin{enumerate}
  \item \textbf{性能表现}：按 2026 年 3 月 23 日这一轮 JMeter 测试结果，500 并发登录平均响应时间为 83.03ms（P95 为 99ms），500 并发热缓存社团列表平均响应时间为 5.18ms（P95 为 8ms），300 并发活动报名与签到平均响应时间分别为 34.02ms 和 27.88ms，错误率均为 0\%。这说明非 AI 核心链路在当前脚本条件下整体比较稳定。但 AI 问答接口在 20 并发压测下平均响应时间约为 62.16s，超时错误率为 50\%，仍然是当前系统最明显的性能短板；

  \item \textbf{并发控制}：通过悲观锁与唯一约束组合机制，系统在本轮 300 并发活动报名与签到脚本下未出现重复写入导致的接口错误，说明其对核心写路径已经具备一定的并发保护能力，但更高并发与长稳场景还需要继续补测；

  \item \textbf{测试基础}：目前已形成覆盖用户、网关、社团与并发边界等模块的自动化测试基础。本轮复跑中，7 个后端测试类共 20 个后端用例全部通过，前端 6 条 Playwright 浏览器用例、3 组导出文件校验、20 条权限矩阵检查和 35 条关键读链路稳定性检查也全部通过。整体看，当前系统已具备较完整的回归验证基础，但集成测试与自动化回归范围还需要继续扩展；

\end{enumerate}

\subsubsection{工程化实践}

\begin{enumerate}
  \item \textbf{容器化部署}：通过 Docker Compose 编排前端、后端、AI 服务、数据库、缓存、消息队列、监控等多个服务容器，实现一键部署；

  \item \textbf{可观测性}：集成 Prometheus + Grafana 监控体系，暴露 JVM、HTTP、数据库、缓存、业务等多维度指标，支持实时监控与告警；

  \item \textbf{安全加固措施}：实现登录失败限频（15 分钟窗口内超过 10 次限制）、输入校验、安全响应头、基于 JPA/参数化访问的数据访问方式以及 Cookie 策略等工程化安全加固措施，并对鉴权边界进行了验证；更完整的 CSRF 专项测试、漏洞扫描与渗透测试还需要后续补强；

  \item \textbf{异常处理}：通过全局异常处理器统一处理各类异常，采用 Logback 实现日志分级和滚动管理，保证系统的可维护性与可追溯性。
\end{enumerate}

\subsection{在当前设计目标下的实现特点}

结合这篇论文的需求范围、架构选择与实现结果，本系统在当前版本中呈现出以下特点：

\begin{enumerate}
  \item \textbf{覆盖社团全生命周期管理}：系统覆盖创建、审批、成员管理、活动管理、招新管理、财务管理、资源管理、解散流程等关键环节；

  \item \textbf{采用模块化单体架构}：在统一部署的前提下保持较清晰的模块边界，为后续演进预留了工程空间；

  \item \textbf{支持关键实时交互场景}：通过 WebSocket 实现活动签到实时广播，并将非关键通知交由异步链路处理，以兼顾实时性与资源消耗；

  \item \textbf{补充成员激励与运营辅助能力}：围绕社团边界实现成员积分档案、活动奖励结算、按角色聚合的统一待办中心和实时运营看板，并在当前原型版本中完成了页面与接口对应关系的运行态核对；

  \item \textbf{引入辅助智能服务原型}：集成 RAG 知识问答与推荐模块，为社团信息查询和个性化入口提供了实现基础；

  \item \textbf{构建认证与权限链路}：采用混合认证机制、多层安全防护、审计日志等措施，并已完成鉴权边界与关键异常路径验证；更完整的 CSRF 专项测试、漏洞扫描与渗透测试仍待补强。
\end{enumerate}

\section{不足分析}

尽管系统已具备可用功能框架，但在工程完善度方面仍存在改进空间：

\begin{enumerate}
  \item \textbf{自动化测试仍不完整}：本轮关键单元测试、多角色浏览器级冒烟测试、权限矩阵校验、读接口稳定性补测与导出校验虽已复跑通过，但自动化覆盖仍集中于部分关键路径，还没有形成覆盖主要控制器、真实依赖交互与跨模块回归的完整体系；
  \item \textbf{安全配置需进一步硬化}：生产环境中的密钥管理、配置隔离与最小权限策略还需要增强；
  \item \textbf{性能基线未形成长期体系}：缺少标准化压测脚本与持续跟踪指标，难以量化版本性能演进；
  \item \textbf{部署高可用能力有限}：当前以单实例为主，还没有形成多副本与故障自动恢复方案；
  \item \textbf{AI 评估仍偏探索性}：问答题集、人工核验标准与推荐效果实验流程还没有完全标准化。虽然已经补充了同批 300 用户的推荐模式对比及机器可读原始记录，但逐题问答判定表、推荐相关性标签和真实在线行为数据仍然不足，因此现有结果主要说明当前方案已经能跑通并具备一定可用性，至于算法效果本身，还不能太早下定论；
  \item \textbf{文献结构仍可进一步学术化}：本轮已在绪论中补充近年的高等教育数字化、教育推荐系统与教育场景 RAG 等同行评审文献，但相关技术章节仍较多依赖官方文档与工程资料；后续可继续提升研究现状与技术分析部分的学术文献密度和综述深度。
\end{enumerate}

\section{未来展望}

后续工作可围绕以下方向持续推进：

\begin{enumerate}
  \item \textbf{完善测试与 CI 体系}：补齐集成测试与契约测试，将关键用例接入流水线，形成稳定回归门禁；
  \item \textbf{推进生产安全治理}：实现密钥统一托管、配置分级、审计告警联动与安全基线检查；
  \item \textbf{演进系统可扩展架构}：基于现有模块边界逐步拆分高负载模块，支持弹性扩容与灰度发布；
  \item \textbf{增强 AI 服务能力}：优化知识库增量更新策略，构建标准化题集、人工标注规范、推荐相关性标签与离线/在线评估指标，引入更细粒度的推荐解释能力；
  \item \textbf{扩展多终端体验}：在现有 Web 能力基础上补充移动端适配与弱网场景优化。
\end{enumerate}

总体而言，本系统已经形成了面向高校社团管理场景的可运行原型，并在安全、并发控制与辅助智能服务方面奠定了比较完整的工程基础。与此同时，自动化回归、长期性能基线、生产环境验证以及更严格的 AI 评估还需要持续补强，这些工作也构成了后续迭代与论文深化的重点方向。
