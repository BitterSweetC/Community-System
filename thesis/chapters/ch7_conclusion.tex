\chapter{总结与展望}

\section{工作总结}

本文围绕高校社团管理数字化需求，完成了一套基于 Spring Boot 的模块化单体系统的设计、实现与阶段性验证。阶段性结果表明，系统在功能完整性、安全机制与主要非 AI 业务路径的性能方面呈现出较好的实现完成度，但 AI 问答链路仍存在明显时延瓶颈；此外，本文各项结论均应限定在当前项目数据、测试脚本与运行环境条件下理解，不意味着系统已经完成严格意义上的全面验证。

\subsection{对研究问题的回答}

结合全文设计、实现与测试结果，本文对绪论中提出的研究问题作出如下阶段性回答：

\begin{enumerate}
  \item \textbf{关于模块化单体架构能否支撑社团全生命周期业务的问题}：从系统实现结果看，模块化单体方案已经支撑了用户、社团、活动、招新、公告通知、资源、财务与 AI 服务等核心业务模块，说明该架构在当前单节点原型场景下具有较好的工程可行性；但其可扩展性结论仍主要基于当前实现与部署经验，尚需多实例、长期运行与更大规模负载进一步验证。
  \item \textbf{关于认证机制与协同通知机制能否满足安全控制和实时交互基本需求的问题}：结合权限行为验证、接口联调与并发脚本结果，JWT、HttpOnly Cookie 与 Redis 会话校验的组合机制能够在当前版本中实现会话控制与主动失效，WebSocket/RabbitMQ 协同机制也能够支撑签到广播与异步通知等典型场景；但当前证据主要覆盖权限边界与关键链路烟测，结论应限定为“阶段性工程可用”，不等同于完整的安全测评或生产级实时系统评估。
  \item \textbf{关于 RAG 问答与推荐模块阶段性可用性的问题}：在项目内部问答核验的聚合统计、同一批 300 个测试用户的推荐模式对比与既定脚本下，RAG 问答与推荐模块表现出一定原型可用性；其中 cf、cb 与 hybrid 三种推荐模式均实现了 300/300 成功且全部返回非空结果，平均时延分别为 273.02ms、276.88ms 和 280.46ms，说明混合策略在当前样本下未明显牺牲服务可用性。然而，AI 问答链路的高时延、高超时率，以及题集原文、逐题判定表、推荐相关性标注、点击/转化日志与在线 A/B 证据的缺失，也表明其现阶段更适宜被界定为探索性工程模块；相关问答核验结果应视为内部观察值而非可独立复算的标准评测结论。
\end{enumerate}

\subsection{主要工作成果}

\subsubsection{功能完整性}

系统实现了覆盖社团全生命周期的八大功能模块，包括：

\begin{enumerate}
  \item \textbf{用户管理模块}：实现用户注册、登录、权限管理、个人信息维护等功能，支持基于角色的访问控制（RBAC）；
  \item \textbf{社团管理模块}：实现社团创建申请、审批、成员管理、生命周期管理（从 PENDING 到 DISSOLVED）等功能；
  \item \textbf{活动管理模块}：实现活动发布、报名、签到码生成与核验、签到记录导出、WebSocket 实时广播等功能；
  \item \textbf{招新管理模块}：实现招新批次管理、动态表单配置、多阶段审核（初审/终审）、名额控制等功能；
  \item \textbf{公告与通知模块}：实现公告发布、站内通知异步分发（RabbitMQ）、前端轮询读取、未读统计等功能；
  \item \textbf{财务管理模块}：实现财务收支记录、审批流程、余额管理、流水查询等功能；
  \item \textbf{资源管理模块}：实现场地与设备资源申请、时段冲突检测、库存校验、审批流程等功能；
  \item \textbf{AI 智能服务模块}：实现基于 RAG 的知识库问答、混合推荐算法，以及知识库初始化与手动补充入口等功能。
\end{enumerate}

系统围绕 18 个核心业务表及 1 个辅助标签表组织主要业务领域，并实现 86 个后端 REST API 接口，形成了较完整的前后端与 AI 服务原型。

\subsubsection{架构与实现特点}

\begin{enumerate}
  \item \textbf{模块化单体架构}：通过 Maven 多模块组织、明确的模块边界与依赖管理，在保持单体应用部署简便性的同时，实现了业务模块的高内聚低耦合，更适合中小型高校场景下的部署与演进；

  \item \textbf{混合认证机制}：结合 JWT 双令牌、HttpOnly Cookie 与 Redis 会话校验，实现了“无状态验签 + 可主动失效”的混合认证方案。该方案既保留了 JWT 的无状态优势，又通过 Redis 二次校验实现了会话的主动失效能力，同时利用 HttpOnly Cookie 防止 XSS 攻击；

  \item \textbf{实时异步协同通知架构}：针对不同场景的差异化需求，设计了分层通知架构。关键实时场景（活动签到）采用 WebSocket 主动推送，非关键通知场景采用 RabbitMQ 异步分发 + 前端轮询读取，有效平衡了实时性与系统吞吐；

  \item \textbf{RAG 增强的知识问答}：将检索增强生成（RAG）技术应用于高校社团管理场景，通过 LangChain Agent 与 Chroma 向量数据库构建知识问答系统。在项目内部自建 200 题题集的阶段性人工核验聚合统计中，该模块表现出一定可用性，但由于仓库尚未保留逐题判定表与题集原文，相关评估流程仍需进一步标准化；

  \item \textbf{混合推荐与冷启动兜底策略}：融合 SVD 协同过滤与语义内容推荐，并在新用户场景下增加热门社团回退机制，以保证无历史行为情况下的推荐可用性。在同一批 300 个测试用户上的模式对比中，cf、cb 与 hybrid 均实现了 300/300 成功与非空返回；hybrid 的平均耗时为 280.46ms，统一 Top-5 口径下的排序结构位于 cf 与 cb 之间，说明融合逻辑能够输出与单一模式不同的候选排序。
\end{enumerate}

\subsubsection{性能与质量保障}

\begin{enumerate}
  \item \textbf{性能表现}：在当前单节点环境与既定 JMeter 脚本下，500 并发登录平均响应时间为 84.08ms（P95 为 98ms），500 并发热缓存社团列表平均响应时间为 6.24ms（P95 为 10ms），300 并发活动报名与签到平均响应时间分别为 33.35ms 和 31.90ms，错误率均为 0\%；但 AI 问答接口在 20 并发压测下平均响应时间约为 68.17s，超时错误率为 65\%，说明外部模型调用链路仍是当前版本最主要的性能瓶颈；

  \item \textbf{并发控制}：通过悲观锁与唯一约束组合机制，系统在本轮 300 并发活动报名与签到脚本下未出现重复写入导致的接口错误，说明其对核心写路径具备一定的并发保护能力，但更高并发与长稳场景仍需继续补测；

  \item \textbf{测试基础}：已形成覆盖用户、网关、社团与并发边界等模块的自动化测试基础；本轮复跑中 6 个后端测试类共 14 个用例和 1 条前端 Playwright 登录流程均已通过，并辅以接口烟测、安全检查与性能压测构成阶段性验证体系；需要指出的是，当前自动化覆盖范围仍然有限，后续仍需继续补齐集成测试与自动化回归测试；

\end{enumerate}

\subsubsection{工程化实践}

\begin{enumerate}
  \item \textbf{容器化部署}：通过 Docker Compose 编排前端、后端、AI 服务、数据库、缓存、消息队列、监控等多个服务容器，实现一键部署；

  \item \textbf{可观测性}：集成 Prometheus + Grafana 监控体系，暴露 JVM、HTTP、数据库、缓存、业务等多维度指标，支持实时监控与告警；

  \item \textbf{安全加固措施}：实现登录失败限频（15 分钟窗口内超过 10 次限制）、输入校验、安全响应头、基于 JPA/参数化访问的数据访问方式以及 Cookie 策略等工程化安全加固措施，并对鉴权边界进行了阶段性验证；更完整的 CSRF 专项测试、漏洞扫描与渗透测试仍需后续补强；

  \item \textbf{异常处理}：通过全局异常处理器统一处理各类异常，采用 Logback 实现日志分级和滚动管理，保证系统的可维护性与可追溯性。
\end{enumerate}

\subsection{在当前设计目标下的实现特点}

结合本文的需求范围、架构选择与实现结果，本系统在当前版本中呈现出以下特点：

\begin{enumerate}
  \item \textbf{覆盖社团全生命周期管理}：系统覆盖创建、审批、成员管理、活动管理、招新管理、财务管理、资源管理、解散流程等关键环节；

  \item \textbf{采用模块化单体架构}：在统一部署的前提下保持较清晰的模块边界，为后续演进预留了工程空间；

  \item \textbf{支持关键实时交互场景}：通过 WebSocket 实现活动签到实时广播，并将非关键通知交由异步链路处理，以兼顾实时性与资源消耗；

  \item \textbf{引入辅助智能服务原型}：集成 RAG 知识问答与推荐模块，为社团信息查询和个性化入口提供了实现基础；

  \item \textbf{构建较完整的认证与权限链路}：采用混合认证机制、多层安全防护、审计日志等措施，对认证控制与权限隔离路径进行了较系统的工程实现。
\end{enumerate}

\section{不足分析}

尽管系统已具备可用功能框架，但在工程完善度方面仍存在改进空间：

\begin{enumerate}
  \item \textbf{自动化测试仍不完整}：本轮关键单元测试与前端登录流程虽已复跑通过，但自动化覆盖仍集中于部分关键路径，尚未形成覆盖主要控制器、真实依赖交互与跨模块回归的完整体系；
  \item \textbf{安全配置需进一步硬化}：生产环境中的密钥管理、配置隔离与最小权限策略仍需增强；
  \item \textbf{性能基线未形成长期体系}：缺少标准化压测脚本与持续跟踪指标，难以量化版本性能演进；
  \item \textbf{部署高可用能力有限}：当前以单实例为主，尚未形成多副本与故障自动恢复方案；
  \item \textbf{AI 评估仍偏阶段性}：问答题集、人工核验标准与推荐效果实验流程尚未完全标准化。尽管当前已补充同批 300 用户的推荐模式对比及机器可读原始记录，但仍缺少逐题问答判定表、推荐相关性标签与真实在线行为数据，现有结果更适合作为工程可用性观察，而非严格的算法结论；
  \item \textbf{文献结构仍可进一步学术化}：本轮已在绪论中补充近年的高等教育数字化、教育推荐系统与教育场景 RAG 等同行评审文献，但相关技术章节仍较多依赖官方文档与工程资料；后续可继续提升研究现状与技术分析部分的学术文献密度和综述深度。
\end{enumerate}

\section{未来展望}

后续工作可围绕以下方向持续推进：

\begin{enumerate}
  \item \textbf{完善测试与 CI 体系}：补齐集成测试与契约测试，将关键用例接入流水线，形成稳定回归门禁；
  \item \textbf{推进生产安全治理}：实现密钥统一托管、配置分级、审计告警联动与安全基线检查；
  \item \textbf{演进系统可扩展架构}：基于现有模块边界逐步拆分高负载模块，支持弹性扩容与灰度发布；
  \item \textbf{增强 AI 服务能力}：优化知识库增量更新策略，构建标准化题集、人工标注规范、推荐相关性标签与离线/在线评估指标，引入更细粒度的推荐解释能力；
  \item \textbf{扩展多终端体验}：在现有 Web 能力基础上补充移动端适配与弱网场景优化。
\end{enumerate}

总体而言，本系统已经形成了面向高校社团管理场景的可运行原型，并在安全、并发控制与辅助智能服务方面奠定了较为完整的工程基础。与此同时，自动化回归、长期性能基线、生产环境验证以及更严格的 AI 评估仍需持续补强，这些工作也构成了后续迭代与论文深化的重点方向。
